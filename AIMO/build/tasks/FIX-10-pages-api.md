**Owns:** `src/tta/ui/`, `tests/ui/`, `src/tta/api/` (including `mcp_surface.py`), `tests/api/`, `tests/mcp/`, `tests/e2e/`. **Hand-backs:** `T09.md`, `FIX-8.md`, `T11.md`, `T12.md`, `T13.md`, `T14.md`. **Read:** SPEC §2, §12; `docs/DEMO.md`.

## Decided by the orchestrator
**A private sandbox per browser for the pages.** In dev and demo, each browser session of the pages gets its own order book: its own in-memory SQLite store, its own audit trail, its own offer service and order book, built over the shared catalog, supplier gateway (with its fall-back and budget), policy engine, request parser and agent runner. So one visitor's orders never count in another's day, never appear on another's approvals page, and the demo always starts from an empty book. At most 300 sandboxes (least recently used dropped), dropped after 2 hours idle; a "Start again" button on the pages empties the visitor's own sandbox (POST, CSRF). Every page says, in one line, "Your own demo order book: nothing you do here is seen by other visitors, and it commits nobody." The REST API and MCP, with their tokens, keep the shared order book as today. `docs/DEMO.md` says this (you own `tests/e2e/`; edit `docs/DEMO.md` too).

## Findings to fix
1. **HIGH — the shared order book** (Python 1, security 3 and 7, questions T12-1, T13-1, T14-2): the sandbox above. The sandbox factory lives in `src/tta/api/` (for example on `Parts` or the `SurfaceContext`), the pages use it.
2. **HIGH — one visitor fills every global ceiling** (security 1, Python 3b, security 4): per-visitor windows **per kind**, keyed by the client address alone (not identity plus address), each well under its ceiling: lookups (offers and substitute searches) 20 a minute, orders and decisions 20, model runs and readings 5; global ceilings unchanged (120, 120, 30), live supplier looks 6 a minute overall and 2 per visitor. Named constants. Tests that one address with both agent tokens cannot reach a ceiling, and that a second address is still served.
3. **HIGH — `X-Forwarded-For` is trusted at its leftmost entry** (security 5, Python 3a): trust no forwarded header unless a setting says how many trusted proxy hops there are (`TTA_TRUSTED_PROXY_HOPS`, default 0: use the peer address; on Modal the documentation says the peer address is the visitor's); with N hops take the N-th entry from the right. Key an IPv6 address on its /64. You may add the field to `src/tta/config.py` (one field, with a test in `tests/test_foundation.py`).
4. **HIGH — a second order on resend** (Python 5, silent 1): the pages' run of a request uses one idempotency key per form submission (derived from the form's run key), never releases a run key once an order exists, and a resend shows the first result. `/v1/agent/run` returns the run the runner returns (FIX-9 makes it return after a failure with the order in it); never a 500 that hides an order.
5. **HIGH — a reading from a recording is not labelled** (silent 2): `Gateway.read_request(identity, text) -> Reading` (call `parser.read` when the parser has it, else `parse_request` with source MODEL and the hook's model id); `POST /v1/requests/parse` keeps its body and adds headers `TTA-Read-By` (model id or `hand-built`) and `TTA-Reading-Source` (`model`, `recording`, `hand-built`); the pages show the reading's sentence wherever the "how it was read" line is.
6. **MEDIUM — the approver form does not carry the approver** (Python 4): the decision form carries the approver id shown on the card; the server refuses (409-like problem, `invalid-request`) when it differs from the cookie's approver at submit time, saying that the approver was changed in another tab.
7. **MEDIUM — the pages read a sentence twice after the agent fails** (Python 6, 9; silent 6): use the run's reading; never call the parser again for the same submission.
8. **MEDIUM — every view of a result page looks up substitutes again** (Python 7, security 8): compute the ranked substitutes once, at run time, and keep them with the run; a view without the run shows a "Look up substitutes" button (POST) instead of looking up.
9. **MEDIUM — the MCP endpoint keeps event streams open** (security 6): `GET` and `DELETE` on `/mcp` and `/mcp/` answer 405 before the SDK, with a test that the answer comes at once.
10. **MEDIUM — the database can be grown fast** (security 2): in dev and demo, a request through REST or MCP has at most 5 lines (a named constant; `invalid-request` above it); the audit facts of an offer list exclusions once per product, not once per line (in `tta.api.service` where it builds the context; do not edit `tta.audit`); measure the bytes per offer before and after in the hand-back.
11. **LOW — a result page can deny an order that exists** (Python 8, silent 9): `Gateway.order_for_offer(identity, offer_id) -> Order | None` (read through the store, not the 100-newest list); the page uses it; a page whose run is no longer in memory says so ("how this was read is no longer known").
12. **LOW — page wording** (silent 8): "No model was asked" only when no model was asked; the agent card names a fall-back run and a hand-built run as what they are; the substitutes card says "Can be ordered, needs approval" for a candidate whose quantity is not confirmed (T13 note).
13. **LOW — `/docs` loads an unpinned CDN script on the pages' origin** (security 10): pin an exact Swagger UI version and set a Content-Security-Policy on `/docs` and `/redoc` that allows only that CDN and `frame-ancestors 'none'`; add subresource integrity if you can obtain the hash from the CDN.
14. **LOW — the assumptions page says "not written" when the file is too big** (silent 11): say what is true.
