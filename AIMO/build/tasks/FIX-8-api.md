## Findings to fix
1. **HIGH — an offer can mix a live price with replayed stock and say only "replay".** `fallback.py` (`_ask`) picks live or the capture per call; `offers/deps.py` (`look_up`) makes two calls and labels the whole look with the availability answer's source and time. Reproduced two ways (budget at exactly 10; availability failing after a live price). Fix: the port `PairedLookup` now exists in `tta/contracts/ports.py`. `FallbackGateway.look_up(ids, fresh=False)` answers price **and** availability from one source: both live, or — if either live call fails, or the budget cannot cover both — both from the capture. `offers/deps.py` `look_up` calls `gateway.look_up` when the gateway is a `PairedLookup` and two calls otherwise, and in every case refuses (as `SupplierUnavailable`) a pair whose two sources differ. The re-check before an order goes the same way.
2. **MEDIUM — the data clock is one shared variable that follows the last answer of any request.** `fallback.py` (`_last_source`, `_SourceClock`). Decided: in live mode the data clock is always the live clock (real time, the supplier's `timeNow` carried forward), also while answers come from the capture; in replay mode it is pinned. An offer built from the capture still carries the capture's `time_now` and `source: replay`. Remove the source-following clock. `source` on `/healthz` is the source of the last completed look, read and written under the lock, and `null` before the first one (never "live" on the strength of the budget alone).
3. **HIGH — live mode with a client that cannot be built starts on the capture.** `wiring.py` (`_gateway`): a base URL the client refuses (not https) is logged and the app serves the capture for the life of the process. A configuration error stops the start; only an outage or a spent budget falls back.
4. **HIGH — one visitor can lock every other visitor out, and can spend the supplier and model budgets.** The demo tokens are public and shared, the limiter keys on the identity id, and the pages act as the same identities. Fix, in `limits.py` and `service.py`:
   - A small ASGI middleware on the root app puts a **client key** into a context variable for the request: the first address of `X-Forwarded-For` when the direct peer is a private or loopback address, else the peer address. The limiter's key for a demo identity is the identity id plus the client key, so each visitor has its own window (60 per minute). Tokens from the environment keep the identity id alone.
   - **Global ceilings per minute**, whoever calls: offers and substitutes together 120; orders and decisions together 120; `parse_request` and `run_agent` together 30. Above a ceiling the answer is `rate-limited` with `Retry-After`.
   - **Live looks at the supplier: at most 6 per minute for the whole process** (a named constant). Above that the paired lookup answers from the capture, labelled replay; it is not an error.
   - Unauthenticated requests (401) are not counted and cost nothing but the token check.
5. **MEDIUM — `/healthz` is public, unlimited, and reads the whole audit trail each time.** `AuditTrail.head()` keeps the count and last hash in memory after the first read and after each event it writes, and re-reads only when `store.last_audit_hash()` differs from what it holds. `/healthz` drops the budget number and keeps the true-or-false settings. Its `status` is `ok` or `degraded`, with `reasons` (for example "live looks are paused after a supplier failure", "the call budget is low", "answers come from the recorded capture while live mode is asked for").
6. **MEDIUM — a validation error below the route is reported as the caller's fault.** `errors.py`: only FastAPI's `RequestValidationError` (and a `ValidationError` raised where caller input is turned into a model) is `invalid-request`. Any other `ValidationError` is a 500 problem with a generic detail, and the trace goes to the log.
7. **MEDIUM — a module that exists without its factory is treated as absent.** `hooks.py`: when `tta.agent` exists and defines neither factory, stop the start with `HookError`; when it defines only one, log a warning naming the missing one.
8. **MEDIUM — failures after the store is opened leak it.** `wiring.py`, `app.py`: close what was opened when a later step of `build_parts` or `create_app` raises; `Parts.close` closes each part even when an earlier close raises. Tests for both, and a test that the live client is closed on shutdown (the present test checks the store only).
9. **MEDIUM — `/openapi.json` builds its examples on the event loop and can cache an incomplete document.** `docs.py`, `examples.py`: build the examples once at start-up (in the lifespan, off the loop); when a scenario fails, log it and serve the document without that example, saying in the document's description that an example could not be built; never a 500 for the document.
10. **MEDIUM — "request received" is not in an order's trail (question T09-1).** `service.py`: `create_offer` writes `request.received` itself, first, with the offer id, from the `text` of the request's lines (the buyer's own words, kept on each line). `parse_request` and `run_agent` write `request.received` only when no offer follows, that is when parsing fails. One "request received" per offer, never two.
11. **LOW — the body limit raises on a non-ASCII digit.** `limits.py` (`_declared_length`): `"²".isdigit()` is true and `int()` then raises outside the error handlers. Use `isascii() and isdigit()`; a test with a raw ASGI call.
12. **LOW — tokens from the environment are not checked.** `identity.py`: outside dev and demo, a token shorter than 24 characters, a token mapped twice, or two tokens with the same identity id stop the start (the error names positions, never a token).
13. **LOW — no security headers.** Every response: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`; every `/v1` response also `Cache-Control: no-store`. The pages (T12) set their own Content-Security-Policy.
14. **LOW — `/v1` without a slash.** `app.py` (`_PagesMount`): the exact path `/v1` belongs to the API too.
