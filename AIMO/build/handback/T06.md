# T06 — done

## Built
- `src/tta/store/sqlite_store.py` — `SqliteStore(path=":memory:")` implements the `Store` port on `sqlite3`: one connection behind a lock (usable from the FastAPI thread pool), WAL on a file, whole contract object as JSON text per row with Decimals as strings (exact round trip). `open_store(settings)` takes the path from `settings.db_path` and creates the folder. SQLite errors become `SupplierUnavailable`.
- `src/tta/store/schema.py` — tables (`offers`, `orders`, `approvals`, `idempotency_keys`, `audit_events`) and every statement as a constant; no SQL is built from input. Audit events have an insert and two selects, nothing else.
- `src/tta/audit/trail.py` — `AuditTrail(store, clock, policy=None)` implements `AuditSink`: `record` (CloudEvents 1.0 envelope, chained, appended), `view`, `verify_chain`. No other public member.
- `src/tta/audit/chain.py` — canonical JSON, `event_hash` (SHA-256 hex), `verify_events` → ok, or the first event that was changed or does not follow the one before.
- `src/tta/audit/sentences.py` / `supplier_sentences.py` — one template per event type (all 15 of `AuditEventType`) for each reader.
- `src/tta/audit/phrases.py` — money, quantities, dates, lists, roles, "698 ST of 463380 … for €1,980.77 net"; no locale.
- `src/tta/audit/facts.py` — compact facts per reader; the supplier's are an allow-list.
- `src/tta/audit/readers.py`, `views.py`, `scope.py` — what the supplier may see, event selection and projection, ids/option/decision read from the context.
- `src/tta/audit/__init__.py` — docstring table: what each event type reads from `AuditContext`.
- Tests: `tests/store/` (20), `tests/audit/` (102).

Wiring for T08/T09: `store = open_store(settings)`; `audit = AuditTrail(store, clock, policy=engine)` — **one per process**.

## Assumptions
- One hash chain for the whole trail, not one per order as in `LOG-FORMAT.md`; the first event's previous hash is 64 zeros (`GENESIS_HASH`).
- Hash = SHA-256, hex, over the event as `model_dump(mode="json")` without `data.hash`, keys sorted, no spaces, UTF-8. Numbers are written as Python's `json` writes them; this is not RFC 8785.
- `verify_chain` reads `checked` as the number of events examined, the bad one included.
- The chain shows a changed, removed or inserted event. It does not show the last events being removed, nor a full rewrite of every hash; that needs the head hash kept by the other party.
- One `AuditTrail` per store and process. Two processes writing one database can give two events the same previous hash.
- `rule_ids` holds each rule id once, although a line rule fires once per line; every firing stays in `facts.decision.fired`.
- Rule sentences and the decision's sentence are quoted from the policy decision, never rebuilt here.
- Supplier view hides: approver id, name, role and note; every P- rule and F-02; every rule sentence; the pasted text and a request line's own words; allergen exclusions and strictness; the profile; exclusion counts for `ALLERGEN_DECLARED` and `ALLERGEN_NOT_STATED`; offer notes; option title, summary and constraint checks; the allergen claim status; required roles; approval reasons; `status_sentence`; evidence beyond product id and found.
- Supplier view shows: the agent's id and name, lines, prices, totals, availability, the reliance statements, `placed_by`, and rules F-01, F-03, F-04, F-05, F-06 with the meaning of SPEC §7.
- Caller facts (`AuditContext.facts`) are buyer-only, except `products_looked_up`, `product_ids`, `source`, `time_now`.
- Facts are summaries, not copies: exclusions are counts by reason, the full offer is read by id. Largest event in the sample flow is about 9 KB (CloudEvents guidance: 64 KB).
- The trail of an order = its events plus the events of its offer that belong to no order.
- A buyer's view must name an order, an offer or a profile (`InvalidRequest` otherwise). Whether that order belongs to the caller is checked by the caller.
- Any reader that is not exactly `buyer` gets the supplier projection; an unknown reader is `InvalidRequest`.
- Event `time` is the `Clock` port's: in replay every event carries the pinned time.
- Times in sentences keep the offset they carry ("17:00 (UTC+02:00)"); nothing is converted to Helsinki time.
- Quantities in sentences are in sales units, money is net of tax (`LOG-FORMAT.md` rules 4 and 5).
- `subject` is null on an event about nothing stored yet (CloudEvents JSON allows null for unset).
- Needs SQLite 3.38 or later (`json_valid`, `json_each`, upsert); the virtualenv has 3.51.
- A duplicate audit event id is a `ValueError`, not a typed error: it is a programming fault, not a caller's.

## Contract changes needed
- `AuditContext` / `AuditData`: no request or correlation id. `request.received`, `request.parsed` and `lookup.performed` appear in an order's trail only when the caller passes `offer_id`. Either callers do that (works today) or add a `request_id`.
- Hash format: T05 writes `policy_hash` as `sha256:<hex>`; `GENESIS_HASH` fixes event hashes as bare hex. Both are stored as given; pick one.
- `Store.list_audit_events`: filters are AND only, so `view` reads every event and selects in Python. Fine for the demo; a port method for "order or its offer" would be needed at volume.
