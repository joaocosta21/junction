## Built
- `src/tta/store/postgres.py` — `PostgresStore(url: SecretStr, schema="tta")` behind the `Store` port, psycopg 3.3.9.
  - One autocommit connection behind an RLock, as the SQLite store.
  - `atomic()` is one transaction; a nested block is a savepoint.
  - BEGIN, SAVEPOINT and RELEASE wait and go with the block's next statement in one pipeline. A block that ran no statement sends nothing. A COMMIT the server answers with ROLLBACK raises.
  - A transaction left open by a failed commit is rolled back before the next call. A lost connection is reopened at the next call outside a block.
  - Database errors become `SupplierUnavailable` (`55P03` gives "busy"). The trigger's `TA002` becomes `ValueError`; `TA003` or a duplicate `previous_hash` becomes `AuditChainConflict`.
  - Connection errors are logged by class only and never chained.
  - `schema_for(settings)` and `open_postgres_store(settings)`: `dev` uses `tta_dev`; `demo` and `prod` use `tta`.
- `src/tta/store/sql/__init__.py` — every statement as a constant, plus `migrations()`.
- `src/tta/store/sql/001_tables.sql` — the SQLite store's tables. `body` is text; `audit_events.seq` is set by the trigger.
- `src/tta/store/sql/002_audit_append_only.sql`
  - A statement trigger refuses UPDATE, DELETE and TRUNCATE (`TA001`); that covers `ON CONFLICT DO UPDATE` too.
  - A row trigger on INSERT takes an advisory transaction lock, refuses a stored id (`TA002`) and an event that does not follow the head (`TA003`), and sets `seq` = last + 1.
  - Both triggers are `ENABLE ALWAYS`.
- `src/tta/store/sql/003_reader_views.sql` — `audit_buyer` and `audit_supplier`. The supplier view mirrors `tta.audit.views.project(SUPPLIER)`: supplier sentence and facts, redacted actor, rules F-01 and F-03 to F-08 only, no profile.
- `src/tta/store/sql/004_supplier_role.sql` — role `<schema>_supplier`: NOLOGIN, USAGE on the schema, SELECT on `audit_supplier` only. A refusal by the service becomes a warning.
- `src/tta/api/wiring.py` — `_order_book(settings)`: PostgreSQL when `has_database_url`, else SQLite. Any start-up failure of PostgreSQL falls back to SQLite, logs a warning and sets `Parts.start_reasons = (STORE_FALLBACK,)`. New field `Parts.start_reasons`. The sandboxes stay in memory.

## Assumptions
- Live tests run only when the mark expression selects `live` (`-m live`) and `DATABASE_URL` is set. pyproject says `live` is "never selected by default". Otherwise they are skipped with the reason.
- The `tests/store` contract tests are reused by loading their files with `importlib`, which the "no imports from another test module" rule does not foresee. That is the way to run them unchanged on both stores.
- `body` is stored as text, not jsonb (T06's warning about hashes). The views cast it to jsonb.
- `audit_events.seq` is the event's position, set by the trigger under the lock, gapless. An identity column could give a later commit a lower `seq` under concurrent writers and break `ORDER BY seq` against the chain.
- The duplicate-id check and the head check live in the database trigger, under `pg_advisory_xact_lock(<table oid>)`. The Python store only maps the SQLSTATEs.
- The database lock wait (`lock_timeout`) equals the in-process wait, 5 s.
- The triggers are `ENABLE ALWAYS` because the service's admin login may set `session_replication_role = replica` (checked on the service).
- `audit_supplier` also has `offer_id`, `order_id` and `approval_id` columns, to filter by order; the supplier filters by the same ids through the API. It has no profile column. The rule allow-list is written in SQL and tested against `SUPPLIER_RULE_MEANINGS`.
- `audit_buyer` shows every buyer with `profile_id`; keeping buyers apart stays the gateway's.
- The supplier role cannot log in. A login is created by hand (`CREATE ROLE … LOGIN … IN ROLE tta_supplier`, in the doc).
- Schema by environment: `dev` → `tta_dev`, `demo` and `prod` → `tta`, so a laptop never writes into the demo's trail.
- A lost connection fails the call that finds it (503) and is reopened at the next call outside a block. There are no automatic retries.
- Pipeline mode (libpq 14 or later) is required. Without it the store refuses to open and the gateway falls back to SQLite.
- Any start-up failure of PostgreSQL falls back to SQLite, until a restart. The reason has no "sqlite" and no "/" in it, because `tests/api/test_health.py::test_health_shows_no_secret_and_no_path` asserts neither appears on `/healthz`.
- Migrations are idempotent files, run at every start under an advisory lock, with no version table.
- TLS is whatever the URL says. Aiven's URL says `sslmode=require`: encrypted, certificate not verified.
- Connection options: `application_name=tta-gateway`, `connect_timeout=5`, TCP keepalives 30/10/3. These override the same keys in the URL if present.
- **Dropped schema `tta` once.** My code created it when T18 ran the real app locally with `.env` (08:22 UTC, before the environment rule existed). It held one `request.received` event, a photo request that could not be read, and nothing else. Dropping it lets the deployed demo start on a clean trail. The role `tta_supplier` was kept and is reused.
