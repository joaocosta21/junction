## Assumptions
- **SQLite runs on local disk, with a copy on the Volume.** The brief said a Volume for `var/` including the database, so this is a deviation (question 1). The reasons: Modal documents no SQLite use, says Volumes have no distributed file locking, and its only SQLite example copies the database in; SQLite says WAL fails on network file systems. The call budget and the recordings sit on the Volume directly.
- Volumes v1, the default (`create_if_missing=True`).
- The secret is read through `tta.config` on the deploying machine only. In the container the module reads nothing and the Secret is `from_dict({})`, as Modal's own `from_local_environ` does. The base URL is included only when it was set (`model_fields_set`).
- The libraries are pinned to the local `.venv` versions, plus `starlette==1.10.0` because `app.py` overrides `Mount.matches`. Neither `uvicorn` nor `modal` is installed, because Modal serves the ASGI app and brings its own client. A test keeps the pins equal to the installed versions.
- The repository layout is kept under `/app`, so that `tta.config.REPO_ROOT` is `/app` (the pages read `REPO_ROOT/docs/ASSUMPTIONS.md`). Every path setting is also set explicitly.
- `scaledown_window=600`, `cpu=1.0`, `memory=1024`. These values are my choice, not the brief's. At Modal's listed prices one running hour costs about $0.055, and each 10-minute idle tail about $0.01.
- `--strategy recreate` on every deploy. A rolling deploy runs old and new containers together, which would mean two writers of the database copy.
- **Per-visitor rate limits:**
  - Modal's docs say `request.client.host` (the ASGI `client`) is the client's IP, usable for rate limits. The Modal client's runtime source has a comment saying Modal strips `X-Forwarded-For` from the scope.
  - So `client_key_of` keys on the visitor's public address and nothing needs to change. This is inferred, not observed.
  - Visitors behind one NAT (the venue Wi-Fi) share a window.
