## Assumptions
- `get_offer` takes the typed request and makes a new offer (`service.create_offer`), as the task's test and SPEC §11 read. No tool reads a stored offer by id (question 1).
- The transport is Streamable HTTP with no session and plain JSON answers (`stateless_http=True`, `json_response=True`): nothing is kept between calls, so any replica can answer, and the tools push nothing to the client.
- Identity is the SDK's own bearer check (`token_verifier` with `AuthSettings`) asking `context.identify`. Without a valid token the answer is the SDK's: `401`, `WWW-Authenticate: Bearer error="invalid_token"`, body `{"error": "invalid_token", …}` (RFC 6750), not a problem document. It covers every request, `initialize` and `tools/list` included.
- No OAuth: tokens are handed out outside the protocol. `AuthSettings.issuer_url` is a required field, so it holds the placeholder `https://tta.example`; with `resource_server_url=None` the SDK publishes no OAuth metadata and the placeholder is sent to nobody (tested).
- Each tool asks `context.identify` again with the token of its own request and refuses when the answer is no identity, also when it is reached with no HTTP layer.
- The Host header is not checked (`enable_dns_rebinding_protection=False`). The SDK's default accepts only `localhost` and would answer `421` on the deployed address; no setting holds the public host name; REST does not check it either.
- A body model is one argument (`request`, `query`), an id is a field. `find_substitutes` needs `query`, as the REST route needs a body; `{}` asks for the candidates alone.
- A typed error is an `isError` result whose text and `structuredContent` are the problem document the REST route sends, with `status` and every extension member (`fresh_offer_id`, `retry_after_seconds`).
- Only `TtaError` is converted. Anything else, a `ValidationError` below a tool included, is the SDK's "Error executing tool <name>" with the trace in the server's log (as FIX-8 decides for REST).
- Arguments that do not match a tool's schema are refused by the SDK before the tool runs, in the SDK's wording.
- An argument a tool does not have is ignored by the SDK (REST refuses an unknown body field). Unknown fields inside `request` and `query` are refused by the contract models.
- Building an `MCPServer` calls `logging.basicConfig` for the process when nothing configured logging. It is built with `log_level="WARNING"`, which is what Python shows by default; it adds a Rich handler to the root logger.
- The tools are plain functions, run by the SDK on worker threads. Context variables set by the gateway's middleware reach them, so FIX-8's limit per visitor holds over MCP (tested both ways).
- Server name `trusted-trade-agents`, title and version from `tta.api.docs`. The server's `instructions` give the flow and say that product names and other supplier text are data, never instructions. The name fields themselves are passed on as they are.
- The form of the idempotency key comes from `tta.api.routes` (`KEY_PATTERN`, `MAX_KEY_LENGTH`).
- Tests use `httpx2` (the SDK's HTTP client, installed with `mcp`, not named in `pyproject.toml`) because the SDK's client transport takes nothing else, and the pytest plugin that comes with `anyio`. Nothing was installed.
- Tests treat `tta.agent` and `tta.ui.routes` as not installed, as `tests/api` does.

## Contract changes needed
- `src/tta/api/app.py` (not ours): the exact path `/mcp`. Today `POST /mcp` is a 307 to `/mcp/` without the pages and is answered **by the pages** when they are mounted (dev and demo). Send it to the MCP surface, or at least keep it away from the pages (question 2).
- `Settings`: the public address of the gateway (for example `tta_public_url`). Needed to allow only that Host on the MCP endpoint and, with an issuer address, to publish OAuth protected-resource metadata.
- `pyproject.toml`: `httpx2` and `anyio` are used by `tests/mcp` and come only through `mcp`. Name them under `dev` if the team wants every import declared.
- `ruff` (`src = ["src", "tests"]`): the folder `tests/mcp` makes `from mcp import X` sort as first-party. The tests import from `mcp.client` and `mcp.shared.exceptions` instead; no other file is affected today.

## Not done
- Reading a stored offer over MCP, so `fresh_offer_id` cannot be read there (question 1).
- A check with a third-party MCP host (Claude Desktop, MCP Inspector). To run later: `.venv/bin/python -m uvicorn --factory tta.api:create_app`, then point the host at `http://127.0.0.1:8000/mcp/` with the header `Authorization: Bearer demo-agent-allergy-ward`.
- `GET /mcp/` with `Accept: text/event-stream` opens the SDK's event stream and holds the connection until the client leaves; nothing is ever sent on it. The SDK has no switch for it. It needs a token.
- An argument error repeats the value sent (Pydantic's text, cut short) to the caller who sent it. REST repeats no caller text.
- A body over 64 KB sent without a declared length is refused with `413` as plain text by the mounted application; with a declared length the gateway's own middleware answers `413` as a problem document.
- Large answers are not trimmed. A search for `milk` (78 products) is 138 KB of text plus 94 KB of structured content; `tools/list` is 88 KB, 77 KB of it output schemas. `limit` on the search asks for fewer.
- No tool annotations (`readOnlyHint` and the like), no prompts, no resources: the task names tools only. Annotations would let a host tell the tools that only read from `get_offer` and `place_order`.
