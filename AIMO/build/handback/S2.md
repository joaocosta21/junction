## Built
- `src/tta/evidence/answers.py`: `AnswersClient`, one `POST https://api.context.dev/v1/web/answers` per product.
  - Mode `ultra`, deadline 40 s with `behavior: "fail"`, HTTP time-out 50 s, at most 40 calls per process.
  - The task carries the English name, Finnish name and brand only.
  - `EvidenceUnavailable(reason)` covers every failure. No error contains the key or the service's message.
- `src/tta/evidence/reading.py`: `read_answer(record, product) -> Evidence`.
  - Refuses `success: false` or `partial: true`, a non-object `json_content` and non-list `sources`.
  - Keeps the link only when it is http(s), has a host, has no user name or password, and is listed in `sources`.
  - Drops a page that names another product.
  - Removes control and format characters and bounds sizes (200, 80 per term, 20 terms, URL 500).
  - Hashes `json_content` with SHA-256 over canonical JSON.
- `src/tta/evidence/matching.py`: `names_match`. The page name may add no word of its own beyond the English or Finnish name (sizes, brand and "UHT" ignored). It must carry ≥ 60% of the name's words. The brand must appear in the page name, title or host.
- `src/tta/evidence/cache.py`: `EvidenceCache`, one JSON file per product id (request, response, `retrieved_at`), written atomically. Read-only recordings stand behind it.
- `src/tta/evidence/finder.py`:
  - `EvidenceFinder.find_evidence(product)` and `.for_approval(option, decision)`. At most 3 products per approval; one lock, so a product is never paid for twice.
  - `products_needing_evidence`: P-04 fired on the line, and the line has a `TO_HUMAN` finding that is `NOT_STATED` or `UNDECLARED`.
  - `build_evidence_finder(settings, data_dir, catalog)`: returns `None` without a key. Cache in `<data_dir>/evidence/`, recordings in `<fixtures>/evidence/`.
- `src/tta/evidence/wording.py`, `src/tta/evidence/__init__.py`: the sentences and the exports.
- **Call site 1, the order book (`src/tta/orders/`):**
  - `service.py`: an `EvidenceFinder` protocol, and the keyword `evidence: EvidenceFinder | None = None` on `OrderBookService`. In `place_order`, on the APPROVAL path, `for_approval(check.option, check.decision)` runs before `self._write.sent_to_a_human(...)`, so it is outside the `atomic()` block.
  - `records.py`: `awaiting_approval(..., evidence=())` puts the evidence on the approval and adds one reason per piece of evidence found. New `evidence_reasons(evidence, option)`. `approved` keeps those reasons when the order-time decision is re-run.
  - `outcomes.py`: in `sent_to_a_human`, one `evidence.attached` event (system actor) per piece of evidence found, after `approval.requested`, in the same block.
  - `wording.py`: `EVIDENCE_REASON`.

## Assumptions
- The endpoint is Answers alone. Search plus Scrape was not needed: the source page comes back in our shape, and the gateway checks it against `sources`.
- Answers has no per-output `success` flag. A `success: false` is still refused if it appears, and so is `partial: true`. We ask for `behavior: "fail"`, so a partial answer never arrives as a 200.
- Mode is `ultra` (100 credits). `fast` returned another product's page on the first trial.
- The task text includes the Finnish name as well as the English name and the brand. All three are product names, not buyer data. Quotation marks and control characters are stripped, and each name is cut at 120 characters.
- Evidence is looked up only for a line where P-04 fired and a finding is `NOT_STATED` or `UNDECLARED` (as the task notes say). A `MAY_CONTAIN` or an oats-for-gluten case gets none.
- Evidence that found nothing is still attached, so the card says why. It adds no reason and writes no audit event: the event is written only for evidence found, as the task says.
- A not-found result from a 200 answer carries `retrieved_at`. A failure (time-out, refusal) carries none and is not stored, so the next approval for that product tries again. Every 200 answer is stored, including a mismatch or "no page found".
- The lookup runs inside the order book's in-process lock, after the order-time check and before the store transaction. It can hold that book for up to 40 s once for a product that is neither stored nor recorded.
- A pack size is ignored when matching, so the same product in another size counts as the same product. A page in a third language passes only if its words are the product's own.
- "Manufacturer's page" is what Context.dev is asked for. The gateway checks the brand in the page name, title or host, not who owns the domain.
- The finder serves stored answers and recordings in both modes. With a key it also calls Context.dev for a product with no stored answer, in replay mode too: the replay clock is Valio's, not Context.dev's.
- `retrieved_at` is the real UTC time of the lookup, not the pinned replay clock.
- The card shows the evidence first for every approver, not only for a dietitian: one include, one position.
- The reason wording is "Web evidence for product … is attached for the dietitian …". The finder is only asked for P-04 cases, which always go to the dietitian.
- After a partial approval, a reason derived from evidence is kept for the products still in the chosen option.
